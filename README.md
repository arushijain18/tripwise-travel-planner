# ✈️ TripWise – Personalized Travel Itinerary Planner

A full-stack, AI-powered web app that turns a few preferences (destination, dates, budget, interests, pace) into a day-by-day itinerary with attractions, food, stays and transport. Users can save, edit, regenerate single days, share a read-only link and print to PDF.

| Layer      | Tech                                                    |
|------------|---------------------------------------------------------|
| Frontend   | React 18 + Vite + React Router (plain CSS)              |
| Backend    | Python + FastAPI                                        |
| Database   | Supabase (Postgres + Auth + Row Level Security)         |
| AI         | Google Gemini API (free tier) via prompt engineering    |

---

## 1. How it works (architecture)

```
React app ──(login)──────────────▶ Supabase Auth
   │                                   │  JWT access token
   │  Authorization: Bearer <JWT>      ▼
   └────────────────────────────▶ FastAPI backend ──▶ Gemini API  (builds the itinerary JSON)
                                       │
                                       └──▶ Supabase Postgres (trips table, protected by RLS)
```

1. The user signs up / logs in with Supabase Auth in the browser.
2. The React app calls the FastAPI backend and sends the Supabase JWT.
3. FastAPI verifies the token with Supabase, builds a prompt from the form, and asks Gemini for a **strict JSON itinerary**.
4. The backend cleans/validates that JSON (fixes dates, clamps costs, recomputes the total) and stores it in the `trips` table.
5. React renders the itinerary; edits are saved back, and single days can be re-generated by the AI.

### Where the "Generative AI / prompt engineering" lives
Everything is in `backend/llm.py`:
- `SYSTEM_PROMPT` – role + rules (pace, budget, grouping nearby places, JSON only).
- `ITINERARY_SCHEMA` – the exact JSON shape the model must return.
- `_brief()` – turns the form into a structured prompt.
- `_ask_json()` – calls Gemini in JSON mode, retries on rate limits and on broken JSON.
- `normalize_itinerary()` – never trust model output; validate and repair it.
- `regenerate_day()` – re-prompts with context (other days, user instruction such as "make it cheaper") to rewrite one day only.

## 3. Setup guide (about 20 minutes)

**Prerequisites:** Python 3.10+, Node.js 18+, a free Supabase account, a free Gemini API key.

### Step 1 – Supabase
1. Go to https://supabase.com → **New project** (note the database password; you won't need it in the app).
2. Open **SQL Editor → New query**, paste the whole of `supabase/schema.sql`, click **Run**.
3. Open **Project Settings → API** and copy the **Project URL** and the **anon public key**.
4. For easy testing: **Authentication → Providers → Email → turn OFF "Confirm email"** (otherwise sign-ups need an email click before login).

### Step 2 – Gemini API key
Create a free key at https://aistudio.google.com/apikey.
(No key yet? Set `MOCK_LLM=true` in the backend `.env` and the app returns demo itineraries so you can test the UI.)

### Step 3 – Run the backend
```bash
cd backend
python -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env              # Windows: copy .env.example .env  -> then fill in the values
uvicorn main:app --reload --port 8000
```
Check http://localhost:8000/health → `{"status":"ok", ...}` and the auto docs at http://localhost:8000/docs.

### Step 4 – Run the frontend
```bash
cd frontend
npm install
cp .env.example .env              # fill in the Supabase URL + anon key
npm run dev
```
Open http://localhost:5173, sign up, and click **+ New trip**.

| GET    | `/api/shared/{id}`                    | no   | Read-only view of a shared trip          |

## 5. Security notes (good to mention in your viva)
- API keys (`GEMINI_API_KEY`) stay on the server; the browser only has the Supabase **anon** key, which is safe to expose.
- **Row Level Security** in Postgres means a user can only read/write their own rows, even if the backend had a bug.
- The backend validates every request with Pydantic (date order, max 14 days, budget > 0).
- Model output is treated as untrusted and sanitized before saving.

## 6. Deploying (optional)
- **Backend → Render / Railway:** root `backend`, build `pip install -r requirements.txt`, start `uvicorn main:app --host 0.0.0.0 --port $PORT`. Add the `.env` values as environment variables and set `CORS_ORIGINS` to your frontend URL.
- **Frontend → Vercel / Netlify:** root `frontend`, build `npm run build`, output `dist`. Set `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, `VITE_API_URL` (your backend URL). Add a rewrite of all routes to `/index.html` so `/shared/:id` works on refresh.
- In Supabase **Authentication → URL Configuration**, add your deployed frontend URL.

## 7. Troubleshooting
| Problem | Fix |
|---------|-----|
| "Cannot reach the server" | Backend not running, or wrong `VITE_API_URL`. |
| CORS error in browser console | Add your frontend URL to `CORS_ORIGINS` and restart the backend. |
| 401 "Invalid or expired token" | Log out and in again; check `SUPABASE_URL` / `SUPABASE_ANON_KEY` in the backend `.env`. |
| "Database error … relation trips does not exist" | You haven't run `schema.sql`. |
| "Gemini API error 404" | Model name changed; set `GEMINI_MODEL` to a current model from AI Studio. |
| "Gemini busy (429)" | Free-tier rate limit; wait a minute (the backend already retries). |
| Can't log in after sign-up | Email confirmation is on; turn it off (Step 1.4) or confirm via email. |
